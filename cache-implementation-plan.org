** Workflow rules for implementation sessions

Everything below the Work status section is the approved plan. A session
that implements it follows these rules:
1. *Implement only the step the reviewer asks for.* Do not start the next
   step without being asked.
2. *Do not commit.* Do not run =git commit=, =git reset=, =git stash=,
   =git push=, or create branches or tags. The reviewer makes every commit.
   "Each step is one commit" in the Order of work describes how the reviewer
   commits the work, not something the implementing session does.
3. *Do not edit the approved plan.* Change nothing outside this Work status
   section: not the design, the code sketches, the test list, the order of
   work, the acceptance criteria or the decisions. That holds even where the
   work deviates from them. The plan body records what was approved, and
   deviations are recorded here.
4. *When the step's work is done:*
   1. run the full test suite (=uv run -m pytest -q=), the A2 check
      (=uv run python out/cache-redesign-baseline/baseline.py compare=), and
      the type checker ty on the changed modules
      (=uv tool run ty check <files>=; ty is run ad hoc, not added to the
      project). ty finds =.venv= without configuration. Known diagnostics
      that predate this work are listed under Step 2: deviations. Any other
      diagnostic in changed code is fixed, or reported to the reviewer;
   2. report to the reviewer what was done: files changed, test results, the
      A2 result, the ty result, and any deviation from the plan;
   3. then update this Work status section, and only this section:
      - the step's row in the table (status, and a Notes entry that
        summarizes any deviation or points to its subsection);
      - the Stage, Branch and Uncommitted-work bullets;
      - for a significant deviation, a subsection =** Step N: deviations=
        below. It says what the plan specified, what was done instead, and
        why.
5. *If a step cannot be done as planned* and the difference is one the
   reviewer should decide, stop and ask before deviating.

* Purpose and scope

This plan turns the recommendation of =cache-issue-findings-report.org=
(strategy S4 with S2) into concrete changes:
- An *in-memory CGC cache that is always on*.
- A *disk cache that is off unless the user opts in*, by naming a directory.
- An opt-in disk tier that is hardened. It is versioned by convention and has
  self-describing entries, atomic writes, recovery from corrupt entries, and
  worker propagation.

It lists every file to be touched, the proposed signatures, the tests (written
red/green), the order of work, and the acceptance criteria. Implementation
progress is tracked in [[*Work status][Work status]].

The problems being fixed, restated so this plan stands alone:

| ID | Problem                                                                                                  | Fixed by                                  |
|----+----------------------------------------------------------------------------------------------------------+-------------------------------------------|
| F1 | =set_cache_dir()= is process-local; =spawn=/=forkserver= workers revert to the default =./CGC_Data=       | Environment variables + =Pool= initializer |
| F2 | Disk entries record no provenance; a pyclebsch upgrade silently serves stale (or mixed) CGCs            | Disk off by default; version namespace + header check |
| F3 | Non-atomic writes; concurrent first runs crash with =EOFError=; a corrupt file crashes every later run  | Atomic writes; self-healing reads; disk off by default |

* Design overview

** Lookup order

For each cache entry, the lookup goes:
1. *memory* (always on);
2. *disk* (only if a directory is configured);
3. *compute*.

On a disk hit the entry is also stored in memory, and on a compute it is
stored in memory and, if enabled, on disk.

** What is an entry, and what is its key

Unchanged from today, there are two kinds of entry:
- *highest*: the highest-weight CGCs for all multiplicity copies of a sum irrep.
- *lower*: all states of one multiplicity copy.

A key has these fields:
- =kind=;
- =product=: the i-weights, converted to plain =int= tuples and normalized,
  *in the order given*. The key does not re-sort, because the computation
  assumes the order it is handed, and =calc_cgcs= already sorts before
  calling in;
- =sum_irrep=: plain =int=s, normalized;
- =mult_idx=: =None= for highest entries;
- =eps=: the value of =cgc.EPS= at call time. Coefficients below it are
  dropped, so it changes the stored content.

Two separate steps turn a caller's i-weight into key material:
- =standardize_iweight_type= (new) checks that every entry is an integer and
  converts each one to a plain Python =int=. It does not change any value.
- =normalize_iweight= (existing, unchanged) subtracts the last entry from
  every entry, so the last entry becomes 0.

** Defaults and configuration

- The disk tier is off by default, so =get_cache_dir()= returns =None=.
- *The disk tier is only ever used at a path the user names.* There is no
  default location: no implicit =./CGC_Data= and no per-user directory such
  as =~/.cache/pyclebsch=. Concretely:
  - =set_cache_dir= has no default argument;
  - =set_cache_dir("")= raises =ValueError=, because =Path("")= resolves to
    the working directory, which would be an implicit location;
  - an empty =PYCLEBSCH_CACHE_DIR= means "disk tier off", for the same
    reason. A shell line such as =export PYCLEBSCH_CACHE_DIR== therefore
    disables the disk tier rather than pointing it at the working directory.
- *Opting in* works two ways:
  - =set_cache_dir(path)=;
  - setting the environment variable =PYCLEBSCH_CACHE_DIR= before import.
- A path is made absolute when it is set, so a later =chdir= cannot move
  the cache. A leading =~= is expanded first (=Path.expanduser=), then the
  path is resolved (=Path.resolve=). The first step is needed because =Path=
  does not expand =~= on its own. Without it, =set_cache_dir("~/cgc")=, or a
  quoted =export PYCLEBSCH_CACHE_DIR="~/cgc"= (which the shell leaves
  unexpanded), would point at a directory literally named =~= inside the
  working directory. Both =set_cache_dir= and the environment-variable path
  go through the same helper, =_resolve_disk_dir=.
- =set_cache_dir(...)= always clears the memory tier.
- =set_cache_dir(...)= also writes =PYCLEBSCH_CACHE_DIR= (or removes it for
  =None=). Worker processes started by =spawn= then see the same setting,
  including =Pool=s that users create themselves.
  - Scope of that side effect: =os.environ= changes the environment of the
    current process and of processes it starts /afterwards/ (=subprocess=,
    =multiprocessing=). It does not touch the parent shell or any other
    running process.
  - Whether =forkserver= workers of a user's own =Pool= see a change made
    after the fork server started is tested in step 4
    (=test_forkserver_user_pool_sees_later_setting=). The result decides only
    what the documentation says.
- *Optional memory cap:* =set_memory_cache_limit(max_entries)=, default
  =None= (unbounded). With a limit, the least recently used entry is evicted.
  Eviction is always safe, because an evicted entry is simply recomputed (or
  reread from disk). The cap counts entries, not bytes: counting bytes would
  need a size estimate per table, which is more machinery than a cap is worth
  here.
- pyclebsch's own site-factor =Pool= also passes the setting explicitly
  through an initializer, which does not depend on environment inheritance.

** Disk layout and entry format (opt-in tier)

- Layout: =<disk dir>/v<CGC_CACHE_VERSION>/<product dir>/<entry file>=.
  - The product directory and entry file keep today's readable style, built
    from plain =int= tuples, e.g. =[(1, 0, 0), (1, 1, 0)]/lower_weight_CGC_((2, 1, 0), 1)=.
  - When a name would exceed =MAX_ENTRY_NAME_BYTES=, the SHA-256 hex digest
    of the key is used instead. The header (below) makes that safe.
  - Entries written by today's code sit outside any =v<N>= directory, so they
    are never read.
- Each file is a pickle of an envelope:
  #+begin_src python
  {
      "format_version": CACHE_FORMAT_VERSION,  # layout of this envelope
      "cgc_cache_version": CGC_CACHE_VERSION,  # CGC conventions
      "key": {"kind": ..., "product": ..., "sum_irrep": ..., "mult_idx": ..., "eps": ...},
      "pyclebsch_version": "0.2.0" or None,    # None if pyclebsch is not installed
      "pyclebsch_commit": "cb35b4e…" or None,  # None for PyPI and editable installs
      "data": <the CGC table>,
  }
  #+end_src
- On read, the entry is rejected (warn, delete, treat as a miss) if any of
  these hold:
  - unpickling fails;
  - =format_version= or =cgc_cache_version= differs from the current value;
  - the stored key differs from the requested key.
  The last check catches files copied or merged into the wrong place, and a
  changed =EPS=.
- =pyclebsch_version= and =pyclebsch_commit= are informational and never
  checked.
- *Writes are atomic.* The entry is pickled to a temporary file in the same
  directory, then moved onto its final name with =os.replace=, which is an
  atomic rename on the same filesystem. Readers see either no file or a
  complete one.

** Copies and aliasing

- The cached functions =_highest_weight_cgcs= and =_lower_weight_cgcs= are
  private. They return the stored objects, which must not be mutated.
- =calc_cgcs= is the only public way to get CGCs. It reads the stored objects
  directly, which is safe because every value it returns is a freshly built
  dict (its =reorder= step rebuilds each level). A prototype confirmed this
  for all four call forms.
- Today's public =calc_highest_weight_cgcs= and =calc_lower_weight_cgcs= are
  removed from the public API. Nothing outside =cgc.py= calls them: not
  =run/=, not the tests, and not psun, ymcirc or matrix-elements-C. So no
  public path hands out cached objects, and no copying is needed anywhere.
  - For reference: a prototype that exposed stored objects let a caller
    corrupt later =calc_cgcs= results by up to 9.
  - Copying on every read would have cost 0.66 s of 1.67 s in the 2×2×2
    benchmark.

* User-visible behavior changes (release notes for 0.2.0)

1. *No disk writes by default.* Computed CGCs live in memory for the life of
   the process. To persist them across runs, call =set_cache_dir(path)= or set
   =PYCLEBSCH_CACHE_DIR=. There is no default location: the disk cache is only
   used at a path you name, and =set_cache_dir("")= raises =ValueError=.
2. =get_cache_dir()= returns =None= by default. A path that is set is returned
   as an absolute path, with a leading =~= expanded to the home directory.
3. Existing =CGC_Data= folders are never read. They can be deleted.
4. =set_cache_dir()= clears the in-memory cache and updates =PYCLEBSCH_CACHE_DIR=.
5. =calc_highest_weight_cgcs= and =calc_lower_weight_cgcs= are removed from
   the public API; use =calc_cgcs=, which covers every access pattern (all
   irreps, one irrep, one copy, one state, one coefficient). They assumed a
   sorted product without checking it; =calc_cgcs= sorts for you.
6. i-weights must have integer entries. numpy integers are accepted and
   converted to =int=, so sum-irrep keys in =calc_cgcs= results are plain

7. New public helpers: =clear_memory_cache()=, =cache_stats()= and

    """Cached. Returns the shared table: callers must not mutate it, and
    product_irreps must already be sorted (calc_cgcs guarantees both)."""
    key = CacheKey.highest(product_irreps, sum_irrep, EPS)
    return _cache.get_or_compute(key, lambda: _compute_highest_weight_cgcs(key.product, key.sum_irrep))


def _lower_weight_cgcs(product_irreps: tuple[IrrepWeight, ...],
                       sum_irrep: IrrepWeight, mult_idx: int) -> LowerWeightTable:
    """Cached. Returns the shared table: callers must not mutate it, and
    product_irreps must already be sorted (calc_cgcs guarantees both)."""
    key = CacheKey.lower(product_irreps, sum_irrep, mult_idx, EPS)
    return _cache.get_or_compute(key, lambda: _compute_lower_weight_cgcs(key.product, key.sum_irrep, key.mult_idx))

#+end_src

* Decisions for the reviewer

Status after the reviewer's responses of 2026-09-24, 2026-09-27 and
2026-09-28. Answers to individual questions do not approve the plan as a
whole.

1. *=set_cache_dir= writes =os.environ=. Resolved: yes.* The condition was
   that it affects only child processes and nothing else outside the original
   process. That holds. Changing =os.environ= alters the environment of the
   current process and of processes it starts afterwards (=subprocess=,
   =multiprocessing=). It cannot reach the parent shell or any other running
   process.

   One in-process detail: other code in the same process that reads
   =os.environ["PYCLEBSCH_CACHE_DIR"]= would see the new value, but only
   pyclebsch reads that variable.
2. *=forkserver= semantics. Resolved: this is a test, not a decision.* It is
   now =test_forkserver_user_pool_sees_later_setting= in step 4, and its
   outcome decides only the README wording.
3. *Readable names with a hashed fallback. Resolved: adopted.*
4. *Public or private =calc_highest_weight_cgcs= / =calc_lower_weight_cgcs=?
   Resolved: private.* Only =cgc.py= calls them. No caller exists in =run/=,
   the tests (comments only) or psun, ymcirc and matrix-elements-C. Making
   them private removes an unchecked sorted-input precondition from the
   public API and removes any need for copying. The cost is losing direct
   access to raw sorted-order tables. =calc_cgcs= covers every documented
   access pattern, though fetching only highest-weight CGCs through it also
   computes the lower-weight table for that copy. The body of this plan
   (copies and aliasing, release note 5, files table, =cgc.py= code, tests)
   reflects this.
5. *Memory size cap. Resolved: implement now, default =None=.* It costs one
   constructor argument, an =OrderedDict= with =move_to_end= on hits and
   =popitem(last=False)= over the cap, a setter, an =evictions= counter, and
   passing the limit through =pool_kwargs()=: about a dozen lines. The design
   overview, code, tests and step 2 above reflect this.
6. *Commit hash in the header. Resolved: record it, informational only.*
   The condition was that =None= is handled and
   documented. It is:
   - =_installed_commit()= never raises. It returns the hash for git installs
     and =None= for index (PyPI) installs, editable installs, uninstalled
     source trees, and unreadable or malformed metadata. This follows what
     =direct_url.json= contains for each install type, checked in this
     investigation on a git install and an editable install, and on numpy as
     an index install.
   - The =None= case is documented where users will look. The =cache.py=
     module docstring has a "Disk entry format" section, and the README
     caching section says the same. The =_installed_commit= docstring has
     the per-install-type table for maintainers.
   - Two tests cover it: =test_installed_commit_handles_all_install_types= and
     =test_disk_entry_header_records_provenance=.
   - It is never used for validation. =CGC_CACHE_VERSION=, forced by the
     golden-value test, is the validated version. The reasons: the commit is
     unavailable for PyPI and editable installs, and it would invalidate the
     cache on every commit for git installs.
7. *Version number. Resolved: 0.2.0.*
8. *Explicit path for the disk tier. Resolved on 2026-09-27: required.* The
   findings report mentioned a per-user default such as =~/.cache/pyclebsch=
   for opt-in users; it is not adopted. There is no default location, and
   the empty-string cases are closed: =set_cache_dir("")= raises, and an
   empty =PYCLEBSCH_CACHE_DIR= means "off". See Defaults and configuration,
   and =test_set_cache_dir_requires_explicit_path= and
   =test_empty_env_var_disables_disk_cache=.

* Risks

- *Changed default.* Scripts that relied on persistence across runs will
  recompute each run until they opt in. In the report's measurements, the
  largest single entry (a six-irrep singlet) took 47 s. Mitigation: release
  notes, README, and the environment variable for zero-code opt-in.
- *Thread safety.* Two threads missing on the same key both compute it and
  store identical tables. That wastes time but is correct, and pyclebsch does
  not use threads today.
- *Pickle remains for opt-in disk users (F6).* Replacing it is the separate
  strategy S3, which is deferred. Its problem statement is in
  =disk-cache-backend-replacement-issue.org=.
